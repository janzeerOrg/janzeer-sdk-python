# Conformance

Janzeer's signing scheme is custom (see [wallet-and-keys](wallet-and-keys.md)); a client that deviates by one byte
produces transactions every node rejects. Two artefacts keep every official SDK in line:

1. **Vectors** — `wallet-parity-vectors.json`, generated by the node's own cryptography: mnemonic → seed → key →
   address, a raw-key address, and for each transaction type the exact signed bytes, hash and signature; plus an
   EIP-55 table and an amount-scaling table. This SDK vendors them under `tests/vectors/` and `pytest` reproduces
   every entry. The signature check is exact equality, which only holds with RFC-6979 and low-S.
2. **The end-to-end flow** — `e2e/SPEC.md`, 14 steps against a real network: version gate, account, subscribe,
   build and sign, submit over REST, idempotent resubmit over RPC, finality on another node, exact balance
   arithmetic, the WebSocket notification, and three negative cases (nonce gap, forged signature, bad address).
   `pytest -m e2e` runs it.

Both live in <https://github.com/janzeerorg/janzeer-sdk-conformance>.
